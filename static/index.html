怎么拿到这份 Cookie？（点开看 3 步）
  1. 用浏览器打开 bilibili.com，确认已登录。
  2. 装一个 Cookie 导出插件（如 Get cookies.txt LOCALLY），在 B站 页面点插件 → 导出/复制。
  3. 把导出内容整段粘到上面的框里 → 点「保存并验证」。

没有插件也行：F12 → Application（应用/存储）→ 左侧 Cookies → https://www.bilibili.com → 找到 SESSDATA，复制 Value 列。

⚠️ 别从 Network（网络）面板的请求头里复制 —— 那里的逗号已被编码成 %2C， 是新手最常踩的坑（本工具虽会自动还原，但仍建议走上面两条正规路径）。

🔒 Cookie 等同于账号登录态，仅保存在本机 bili_config.json（已加入 .gitignore）。本工具只把它用于向 B站 请求该账号有权观看的清晰度，不外传。

什么情况下要填代理？（点开看）

分两种部署形态，别一概而论 —— 填错方向会白折腾：

① 跑在你自己电脑上（大陆网络） —— TikTok 在中国大陆无法直连 （实测：DNS 能解析出 IP，但 TCP 443 直接超时），不挂代理就取不到任何数据。 这不是工具的缺陷，任何下载器都一样。

② 部署在境外服务器（如 Render / 海外 VPS） —— 通常直连即可， 代理留空。若解析仍失败，说明该机房出口被 TikTok 拦了：换个机房区域， 或填一个公网可达的代理地址（别写 127.0.0.1， 那在服务器上指的是它自己，必然连不通）。

最常见的做法：开着 Clash / FlClash / v2rayN，不用手填 —— 本工具会自动探测 7890、7897、10809 等常见端口，并实测能否真的连上 TikTok。

⚠ 如果你用的是 SOCKS 端口（如 v2rayN 的 10808），当前 Python 环境没装 PySocks， 会直接报错。改用 HTTP 端口即可（Clash 的 7890 是混合端口，直接写 http://127.0.0.1:7890）；或执行 pip install requests[socks] 后重启服务。

🔒 代理地址只写在本机 tiktok_config.json（已加入 .gitignore）， 不包含任何账号信息，不会外传。
